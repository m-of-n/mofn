## Extension points and who controls them

- **CBOR Tags registry** (iana.org/assignments/cbor-tags) — the primary place new CBOR-typed semantics (dates, bignums, URIs, and third-party formats like COSE, CDDL, and mdoc structures) get a stable number. Tiered policy straight from the page:
  - Tags 0–23: "Standards Action"
  - Tags 24–32767: "Specification Required"
  - Tags 32768–18446744073709551615: "First Come First Served"
  - Designated experts: Christian Amsüss, Thomas Fossati, Francesca Palombini; backup Carsten Bormann. (Source: iana.org/assignments/cbor-tags, retrieved 2026-09-22.)
- **CBOR Simple Values registry** — values 0–19 "Standards Action"; 32–255 "Specification Required"; designated expert Carsten Bormann. This is a small, low-traffic extension point.
- **COSE registries** (Header Parameters, Header Algorithm Parameters, Algorithms, Key Types) — these are where new crypto algorithms and header semantics enter the COSE/CBOR signing ecosystem. Quoted policies per range are in the table above/sources; experts are Francesca Palombini/Carsten Bormann (Header Parameters) and Göran Selander/Derek Atkins/Sean Turner (Header Algorithm Parameters, Algorithms, Key Types).
- **CWT Claims registry** — governs the claim-key extension point for CBOR Web Tokens (feeding EAT, ACE-OAuth, RATS evidence). Experts: Mike Jones, Hannes Tschofenig, Ludwig Seitz.
- Net effect: **a small, overlapping set of individuals (Bormann, Amsüss, Palombini, Fossati on the CBOR/tag side; Selander/Atkins/Turner/Jones/Tschofenig/Seitz on the COSE/CWT side) sits as designated expert on nearly every registry that lets the CBOR format itself be extended.** This is a real concentration-of-control point for a reference library to flag: extension of CBOR's core semantics is IETF-governed and free to petition, but gated by a handful of named reviewers.
- Application-level extension points sit one layer up and are controlled by whichever body owns that application: ISO/IEC WG4 controls what goes into an mdoc's CBOR namespaces; the EUDI ARF process controls which attestation formats the EU wallet accepts; RATS WG controls the CoRIM/EAT claim vocabulary that TCG, GlobalPlatform, and the CCC then profile for their own hardware roots of trust.

## Where governance is contested

- **mdoc (ISO/IEC 18013-5, CBOR-based) vs SD-JWT VC (JSON-based) in the EUDI Wallet.** As of ARF v1.4 (per public secondary sources, not the primary ARF text itself in this pass) both formats are mandated for different use cases — mdoc for proximity/in-person presentation, SD-JWT VC for online/PID issuance — rather than one displacing the other. This is a real fragmentation of the "canonical" wallet credential format along CBOR/JSON lines, decided inside the EU's EDICG process rather than by IETF or ISO. **This should be flagged as only partially verified**: the finding is drawn from secondary summaries (walt.id, iGrant.io, MyID.ie), not a direct read of the current ARF PDF/repo text, so the exact wording and version-currency need a follow-up primary-source check.
- **CBOR deterministic-encoding profiles: dCBOR vs Core Deterministic Encoding (CDE).** Blockchain Commons authored an independent "dCBOR" application-profile draft (draft-mcnally-deterministic-cbor); the CBOR WG chairs/participants separately drafted "CBOR: On Deterministic Encoding" (draft-bormann-cbor-det), which the WG then adopted and evolved into the WG item **draft-ietf-cbor-cde** ("CBOR Common Deterministic Encoding (CDE)"). The current framing (per the drafts themselves) is hierarchical/compatible — CDE is the common baseline, dCBOR layers stricter requirements on top for specific applications (e.g. Gordian/Blockchain Commons use cases) — but this converged only after two independently-authored, competing determinism specs existed in parallel inside the same WG. Worth flagging to the library as a case where "the" deterministic-CBOR profile was, for a period, genuinely plural, and adopters shipping against an early draft may not match the eventual WG consensus text.
- **ISO paywall vs. IETF/W3C-style free access.** The mdoc/18013-5 track is normatively load-bearing for the EUDI Wallet and for FIDO/mobile-driving-licence deployments worldwide, yet the base text is only available for CHF 227+ per part from iso.org (or via national bodies), with no redistribution rights. This is a structural friction point for any reference library trying to hold "the" CBOR ecosystem's primary sources: the IETF/IANA/OMA/OCF/C2PA/TCG/GlobalPlatform side of the ecosystem is free to hold and cite in full; the ISO/IEC side (18013-5/-6/-7, 23220, 19566-5 JPEG Trust) cannot be redistributed as bytes, only cited and summarized.
- **Matter/Thread's TLV vs. the wider constrained-computing CBOR consensus.** CSA's Matter uses its own TLV encoding rather than CBOR (no confirmed CBOR usage found in this pass), while OCF (whose Core Specification became ISO/IEC 30118 and which CSA's Matter effort has historical ties to) mandates CBOR. This is a soft fragmentation in the smart-home/IoT space between two IP-based device ecosystems that could plausibly have converged on one binary format and didn't. Flagged as needing a closer technical-dimension follow-up (this is a governance-dimension observation, not a technical one).
