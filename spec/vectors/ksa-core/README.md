# KSA core test vectors

Generated by `generate.py`; consumed by SPEC-0002 Appendix A and SPEC-0003
Appendix A. **Do not edit `vectors.json` or `vectors.md` by hand.**

```sh
python3 -m venv .venv && .venv/bin/pip install cbor2 cryptography
.venv/bin/python generate.py
```

- Signing and hashing come from `cryptography`; no primitive is implemented here.
- Every positive vector is encoded twice — `cbor2` canonical mode and the
  independent `ksa_cbor()` encoder — and the script aborts if they disagree.
- Keys come from fixed seeds; Alice and Bob are the RFC 8032 §7.1 TEST 1 and
  TEST 2 keys, so their public keys can be checked against the RFC.
- Ed25519 is deterministic, so regenerating yields identical bytes.

## Threshold form and the acceptance test

`k` is `threshold` and `n` is the length of `trusts` (`ARCH-0001` §7; SPEC-0002 §8.6).

| vector | case | expected |
|---|---|---|
| TV-9, TV-10, TV-11 | 2 of 3; `k = n`; `k = 1` | verified |
| N-7 | `k = 0` | V8 `kind-rule` |
| N-8 | `k > n` | V8 `kind-rule` |
| N-9 | `n ≠ len(members)`, as an added field | V7 `structure` |
| N-10 | `n ≠ len(members)`, as a disagreeing array head | V5 `encoding` |

**SPEC-0002 V8 owns `1 ≤ k ≤ n`.** `n = len(members)` holds by construction:
there is no `n` field to disagree. Member order in these vectors is bytewise by
kid, which nothing requires yet (`ADR-0004` condition 5).

For DEC-002's acceptance test: `ArtifactStatement` is TV-4, `AuthzCert` is TV-5
and TV-9, and `NameCert` is TV-13 under DV-2 (`ARCH-0002` P6). Reasoning:
`design-log/0019-threshold-fixture/`.

## Locator target withdrawn

**N-11** is TV-4's attestation with `this = [5, uri]`. SPEC-0002 0.6.0 withdrew
target type 5, because a locator binds no digest (`ARCH-0001` R-M-07, R-M-11;
mofn#144). It is well-formed and correctly signed, so only V7 `structure` can
reject it. Reasoning: `design-log/0030-locator-digest/`.

## Delegation and the evaluations block

TV-14…20 are trust and attestation statements under TV-5's
`may-delegate {depth: 1, ranges: [reproducible]}`. `vectors.json` →
`evaluations` gives E-1…E-4: the statement set, the ask, and the SPEC-0004
answer, reason and failing statement. These are **declared**, not computed by
this script; `prototype/wallet/tests/test_delegation.py` checks the wallet
engine's delegation paths (`engine/reduce.py`, T-065) against them
(SPEC-0004 Appendix A asks 3–6; mofn#136).

| eval | case | expected |
|---|---|---|
| E-1 | hop `about` outside `ranges` | no, `widening` |
| E-2 | the same hop within `ranges` | yes |
| E-3 | a second hop with no delegation left | no, `depth` |
| E-4 | onward `depth` larger than what remains | no, `widening` (not clipped) |

Delegation is a requirement (`PLAN-0002` §4.1.1). TV-45…47 and E-23…E-25 add
the cases E-1…E-4 leave out. TV-45 is TV-16 with an earlier `not-on-or-after`;
TV-46 is a second anchor, Carol trusting Alice with `depth: 2`; TV-47 is Alice
passing `depth: 1` on to Bob. The same test checks them against the engine.

| eval | anchor | case | expected |
|---|---|---|---|
| E-23 | TV-5 | the hop has expired; the attestation has not | no, `not-valid-at-time` at TV-45 |
| E-24 | TV-46 | two hops: TV-47, then TV-18 | yes |
| E-25 | TV-46 | the same, but TV-16 passes nothing on | no, `depth` at TV-18 |

## Archives target

DV-3 `library-review` (definer Dave) and TV-21…26 are the archives target of
`ARCH-0001` §2.3.2 (mofn#135). Carol's TV-22 is the anchor in context
`library`. TV-26 is the first **description** target (`SPEC-0002` §7.2 type 6),
a work identified by its title, with its URL carried as a `locator` attribute.
E-5 (yes), E-6 (`no-path`, UC-3's must-fail) and E-7 (yes, the description
target) are in `evaluations`.

**v2, the one archives vocabulary (W-2b, DL-0046).** DV-5 `library-review` v2
(definer Dave) replaces DV-3's type `reviewed` (`yes · partial · no`) with
`record-review` (`reviewed · summarized · unverified`), which the wallet demo
ran as `archives` v1 until W-2b, and keeps `work`, `title`, `locator` and the

Carol's TV-40 is the v2 anchor; TV-41 lets Bob say only `summarized` or
`unverified`. E-20 (yes), E-21 (`no-path`: Bob says `reviewed`) and E-22 (yes,
a description target) are in `evaluations`. DV-3 and TV-21…26 are unchanged.
`prototype/wallet/domains/archives/` copies DV-5, TV-38 and TV-39 and is
checked against them.

## SDSI names

DV-4 `naming` (definer Alice) has one type, `name`, of base kind 12 (`SPEC-0003`
§6.4), so an attribute of it is a **name binding**. TV-27…34 are the bindings,
a trust to a name (TV-31) and a name target (`SPEC-0002` §7.2 type 7). DV-2 and
TV-13 are untouched: DV-2's `name` is base kind text, so TV-13 is not a binding.

`vectors.json` → `resolutions` gives R-1…R-10 and `name_evaluations` gives

checks the wallet engine's resolver (`engine/names.py`, T-040) against them.
They are kept out of `evaluations`, which the test-only delegation walker
reads. Reasoning: `design-log/0039-sdsi-names/`, `design-log/0040-names-resolver/`.
