# DL-0054 — produced

## Engine — `prototype/wallet/`, 0.11.0

- **`make --subject-key` / `check --subject-key`.** `statement.key_target(kid)`
  gives `this = [1, kid]`; `cli.kid_of` resolves a label, a kid prefix
  (`Wallet.find`) or a **full 64-digit kid**, the last so a tag given to a key
  the wallet has never met can still be checked. `--subject`/`--subject-key`
  and `--artifact`/`--subject-key` became required mutually exclusive groups.
  `check.run` takes `artifact: bytes | None` and `subject_key`, and raises
  `ValueError` for both or neither — `cli.main` already turns that into exit 2.
- **The integrity line for a key subject** reports verification alone:
  *"every statement verified; the subject is a key, so there is no copy of
  yours to compare"*, and *not evaluated* when no attestation verified.
  Whether any statement is about that key is reported by authorization and
  acceptance. `_about_what(subject)` returns the literal `"your file"` for a
  digest, so every existing sentence is unchanged, and `render.OTHER_SUBJECT`
  is the key-subject sibling of `OTHER_FILE`.
- **`check --as` / `root list --as`.** `Wallet.anchors(context, persona=None)`
  and `Wallet.contexts(persona=None)` take an owned kid; `None` keeps today's
  union, so `cli.py`, `screens/data.py` and the app's existing callers are
  untouched. `cli.owned_persona` refuses a persona the wallet does not own.
- **JSON.** `subject-target` and `subject-key` at the top level;
  `associations[].subject` gains `target`/`key`/`kid`/`label` **only** for a key
  ask, so the three `associations-*.json` goldens do not move.
- **Fixtures and goldens.** `fixtures/sync.py` gains DV-2, TV-12 and TV-13 —
  copies of published vectors, never hand-edited. Three new goldens, each
  generated by running the command: `key-subject.txt`,
  `key-subject-other.txt`, `associations-key-subject.json`.
- **Tests.** `tests/test_key_subject.py` (11 tests × 2 codecs) and two
  additions to `tests/test_cli.py` for `--as`. 473 → 495 passing.

## App — `prototype/wallet-app/`

- **`mofn_app/verdict.py`**, extracted whole from `pages/verify.py`, so Verify
  and Personas draw the same rows. `OTHER` is now derived from `core.LINES`,
  so the six lines are not written out twice. `subject_card` branches on
  `subject.target`. `Page.restyle()` replaces the `isinstance(page, Verify)`
  test `window.apply_theme` used to single Verify out with.
- **`core.py`**: `Member`, `Community`, `Tag`; `held()`, `received()`,
  `community()`, `communities()`; `contexts(persona)`, `anchors(context,
  persona)`; `check(..., subject_key=, as_=)`, `sign(..., subject_key=)`;
  the pure `members(anchors, labels, owned, known)`; `fingerprint()` and
  `example_definition_id()`. `owned()`/`known()` now sort by label.
- **Personas** — owned and known tables, the full fingerprint, the controller
  kind as `person · self-claimed` (the CLI's own word), the SPEC-0001 §3.1 and
  §3.2 captions, an *Act as* button per other persona, and the tags received,
  each row expanding into its six-line verdict.
- **Communities** — one card per context the active persona relies in: the
  anchors (Trust's five columns) and the derived members, with the spec word
  in the subtitle and a standing caption saying the members are derived.
- **Verify** passes `--as`, offers that persona's contexts, shows a read-only
  *As* row, and clears a verdict when the persona changes.
- **Tests.** `tests/test_personas.py` (18, grouped by acceptance box), 8 UI
  tests, a `two` fixture and `tag()`/`cli_key_json()` helpers. 31 → 58.
